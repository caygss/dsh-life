# 安全边界（模板文档）

> 本文档对应仓库 0.1.0。它描述的是**这套代码本身的边界**，不是一份"照着配就安全"的承诺：
> 你的宿主机、你的协议端、你的模型服务商各自还有自己的边界，那些不在这里。

## 1. 三条定死的规则

| 规则 | 含义 | 后果 |
|---|---|---|
| **插件没有沙箱** | `create()` 以宿主进程的权限运行，能碰到的就是宿主能碰到的 | 安装第三方插件 = 信任它的作者。宿主只记录谁装了什么，拦不住恶意代码 |
| **reserved 不是授权** | `device` / `display` / `vm` 是预留 surface，声明了也拿不到服务 | 不存在"先声明一下试试"的路径；写错 surface 直接拒载，错误码会说是"还没做"还是"没这个门" |
| **模型输出是不可信输入** | 工具参数、要发的消息、写进文件的路径全部来自模型 | 插件做了基础校验（类型、范围、路径根、长度），但业务判断得你自己写 |

## 2. 密钥只从两个地方来

| 位置 | 谁读 | 说明 |
|---|---|---|
| 环境变量名（如 `apiKeyEnv` / `env.onebotToken`） | **宿主**读环境变量，把值交给对应的层 | 配置里写的是**变量名**，不是 key 本身；key 不进仓库 |
| 宿主上的文件（`config.tokenPath` / `config.wsTokenPath`） | 插件读一次，只拿字符串 | 该文件放在仓库外、由宿主自己设权限（建议 600）；插件不缓存、不回显、不写日志 |

几条与之配套的约定，代码里都能查到：

- **插件不读 `process.env`**。宿主只把声明过的键放进 `context.env`（示例宿主就是这么做的），没声明的插件一个变量也看不见。
- **key 不进口志、不进回执、不进错误信息**。模型层请求失败只报 `model_http_<状态码>`，不带 key、不带响应体；`life-qq` 的注释里明确写了"不写 token、不把 token 放进回执或日志"。
- **key 不进模型的上下文**。`memory`（向量）、`net`（搜索/抓取）、`image`（生图）这几道门背后是**宿主**持有的端点和 key，插件只拿到结果，看不见 key。
- **仓库里没有任何真钥匙**。全仓 grep `sk-` / `ghp_` / `AKIA` / `PRIVATE KEY` 是 0 处；`.gitignore` 忽略 `.env`、`*.sqlite`、`data/`。

## 3. 网络暴露面

| 项 | 现状 |
|---|---|
| 默认监听地址 | 示例里的服务全部绑 `127.0.0.1`；仓里唯一的默认端点常量是环回的 `http://127.0.0.1:8080/v1/embeddings` |
| 出网 | 所有出站请求都走 Node 内置 `fetch`，地址来自你的配置；全仓 grep `https?://` 只有一条环回默认值和两句提示文案，**没有硬编码的第三方地址、没有遥测、没有回连** |
| TLS | 仓库里 `rejectUnauthorized` / `NODE_TLS` / `insecure` 出现 **0 次**：没有一处关掉证书校验的开关。要不要走内网明文 HTTP 是你的部署选择，但代码不会偷偷降级 |
| `net` 这道门 | 交给插件的是**宿主自己的 search / fetch 两个动作**，不是通用 fetch：出口、域名白名单、次数上限都在宿主侧 |
| 内网地址 | `web` 插件里有 `url_blocked: 这个地址我不去（内网、本机这类地方不碰）`。**拦截本身在宿主侧**，插件只负责把它翻成一句人话——这条不能只看插件代码就以为防住了 |

对外暴露管理口、协议端、模型端点，是这套代码**管不了**的事。请不要把 OneBot 的 HTTP/WS 直接摊到公网。

## 4. 文件与进程

| 面 | 边界在哪 |
|---|---|
| `hand`（跑命令、读写文件） | 插件**自己不开进程、不碰文件系统**：它调 `context.hands`，每条路径已经过宿主沙箱（landlock 白名单 + ulimit + 超时）。沙箱没装好时它拒绝执行（`no_launcher`），不降级成裸跑 |
| `life-qq` 发媒体 | 只认三个根：`env.homeRoot`、`env.workspaceRoot`（或"屋的隔壁"）、插件自己的 `dataDir`；越界报 `qq_media_path_not_allowed`。**没有"读宿主任意文件再发出去"的路** |
| 收到的文件 | 落在 `<homeRoot>/inbox`；没有 `homeRoot` 就退回插件数据目录（助手读不到）——这是有意的降级，不是失败 |
| 发出去的东西 | 撤回要靠协议端，且有时限。**别把"能撤回"当成安全边界**：消息一旦发出去就已经属于那个账号 |

## 5. 协议端

- 背后是**真实 QQ 账号**。扫码/密码都在协议端那边，本仓库不保存账号密码。
- **两份 token**：HTTP 一份、WebSocket 另一份（协议端的 WS 有独立 token，拿 HTTP 那份打 WS 通常 401）。不填就回落到 HTTP 那份。
- 扩展动作（空间、收藏表情、改资料头像）各家实现差异很大，行为要以你装的协议端为准；验证清单见 [onebot.md](onebot.md)。
- 协议端不是玩具：它同时具备"读历史"和"改资料"两类能力，任何一个被恶意利用，损失都是那个账号的。

## 6. 数据落在哪、谁能读

| 数据 | 位置 | 说明 |
|---|---|---|
| 记忆 / 状态 / 队列 | 插件 `dataDir` 下的 `node:sqlite` 库 | **SQLite 是明文的**：没有加密、没有口令。宿主机上能读这个文件的人就能读到全部记忆 |
| 向量 | 同一批库里，表名带模型名（`emb-<model>`） | 参考实现是自部署的 Qwen3-Embedding-8B、4096 维、走环回；**换模型或换维度必须同时换表名**，旧向量不会自动重算，混用等于把两种坐标塞进一张表 |
| 日志 | 插件 `log()` 与宿主 stdout | 有长度上限；不含 token / key（见第 2 节），但可能含 QQ 号、群号、消息摘要——**日志本身就是要自己管权限的敏感数据** |
| 备份 | 你自己 | 仓库不管备份。备份 = 复制一份明文记忆，复制到哪由你决定 |

撤回（withdraw）的语义是"这条记忆不再参与后续装配"，**不是物理删除、也不是加密擦除**：底层文件里可能仍有痕迹。要真正删，得删库/删整份备份。

## 7. 名单与热改策略

`life-qq` 的"听谁说"和"能发给谁"是两张名单，支持热改（JSON 热文件 > 启动配置 YAML > 内存默认值），并且是**逐键容错**的：

| 情况 | 结果 |
|---|---|
| 某个字段写坏 | 只丢这一格，其余照用；这一格**保持上一次生效值**，并打一条 `policy_partial` warning |
| 某个字段被**删掉** | 才回落（YAML / 默认值）。"删 = 撤"和"错 = 不动"是两条不同的规则 |
| 整份 JSON 语法坏 | 保留最后一次认过的整份策略（`policy_json_invalid`），**不会把人全锁在外面，也不会突然全放行** |

这一点值得单独说：名单读坏时的默认方向是**保持上一次的收紧状态**，不是 fail-open。但默认值本身是 `mode: list` 加空名单，也就是"谁都不理"——要不要放开是你显式写的。

## 8. 我们没有做的事（诚实清单）

| 没做 | 说明 |
|---|---|
| 插件沙箱 | 装插件就是信任。没有签名校验、没有权限声明之外的运行时隔离——`capabilities` 是**功能性**白名单，不是安全边界 |
| 凭证加密 | 没有密钥托管、没有 KMS、没有内存清零。key 在进程内存里，和所有 Node 程序一样 |
| 审计防篡改 | 没有结构化审计日志、没有追加不可改的账本。日志可以被改 |
| 默认限流 | 速率/次数上限有（每日上限、单条长度、媒体大小），但默认值是"不限"或偏宽，要自己按需收紧 |
| 供应链检查 | 零 npm 依赖是现在的状态，不是承诺；CI 只做语法检查 + 示例冒烟，**不做依赖审计、不做 secret 扫描、不做 CVE 扫描** |
| OS 级隔离 | 建议用容器/独立用户跑，但仓库不附带、也不强制 |
| 模型侧隐私 | 你的 prompt、记忆、网页内容都会发给**你选的那个模型服务**。它怎么处理，取决于它的条款，不取决于这份代码 |
| 安全披露流程 | 仓库没有 `SECURITY.md`、没有安全联系人和 CVE 流程。自己 fork 自己用时，请自己留一条上报路径 |

许可（PolyForm Noncommercial 1.0.0，禁止商用）是**法律条款，不是技术控制**：它不阻止任何人运行代码，只规定授权范围。

## 9. 部署检查清单

上手前把这九条过一遍：

- [ ] 所有服务只绑 `127.0.0.1`；要远程访问就套 SSH 隧道或 TLS 反代，别直接开端口
- [ ] key 放在宿主的环境变量或 600 权限的文件里，**没有一处写进配置文件/仓库**
- [ ] 换掉示例里的占位值：假 QQ 号、`qqUserId`、假 token
- [ ] `dataDir` 与记忆库所在目录的权限收紧到只有运行用户可读
- [ ] 名单从"谁都不理"开始，一条一条加；别一上来 `mode: all`
- [ ] 先只装自己写得出的插件；装第三方插件前先读它的 `index.mjs`
- [ ] 备份策略定好，并且知道备份是明文
- [ ] 想清楚"这个助手能对真实账号做哪些动作"：改资料、发群、踢人这几类，出事没有撤销键
- [ ] 保留一条停机路径：停宿主 → 插件不再收消息；这一步永远有效

## 10. 出事怎么办

| 症状 | 处置 |
|---|---|
| 怀疑 token 泄露 | 在协议端重置 token，改 `env.onebotToken` / `tokenPath` 指向的文件；宿主重启后生效 |
| 怀疑 key 泄露 | 在上游吊销并换新 key，改环境变量；旧的请求记录按上游账单核对 |
| 说错话 / 发错消息 | 用协议端的撤回；超过时限就只能道歉。这也是"名单宁紧勿松"的原因 |
| 记忆被污染 | 用撤回把那条移出装配；确认污染面后决定是否重建库（重建 = 丢掉全部记忆，先备份） |
| 插件行为可疑 | 从 `plugins` 列表里去掉它并重启——插件是加载期装配的，去掉就不再运行 |
